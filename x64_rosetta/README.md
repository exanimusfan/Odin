# x64 backend under Rosetta 2 (macOS)

Harness that executes machine code generated by the Odin `-x64-backend` on an
Apple Silicon Mac via Rosetta 2.

UPDATE: a Mach-O object writer now exists (`src/macho_writer.cpp`), so
`-target:darwin_amd64` supports FULL EXECUTABLE builds — `odin build x.odin
-file -x64-backend -target:darwin_amd64` links via clang and runs under
Rosetta directly. Verified: the ENTIRE `examples/demo` (maps, unions,
matrices, complex, big ints, reflection, pthread threading) runs with output
matching the LLVM backend, and `@(thread_local)` uses real Mach-O TLV
(__thread_vars descriptors + dyld tlv_get_addr; per-thread isolation
verified). With `-debug`, DWARF v4 is emitted and lldb does full source-level
debugging via ld64's debug map: file:line breakpoints, source in
backtraces, stepping, and `frame variable` / `p <local>` for locals and
parameters. Scalars, nested structs, fixed arrays, slices `{data,len}`, and
strings (with contents) all inspect correctly, e.g. `p ln` prints the whole
struct tree and `p ln.a.x` drills in. Struct expansion is depth-capped;
unions/maps still show a raw word. This extraction harness remains useful
for testing codegen without linking.

The backend now has two calling-convention implementations behind the seam in
`src/x64_abi.cpp`, selected by TARGET os (`x64_abi_win64`):

- **Win64** (`-target:windows_amd64`) — original, unchanged: unified register
  slots RCX/RDX/R8/R9 + XMM0–3, caller shadow space, `__chkstk` probes,
  odd-sized aggregates by pointer.
- **SysV** (`-target:darwin_amd64` / `linux_amd64`) — full eightbyte
  classification: ≤16-byte values (structs, strings, slices, `any`, i128,
  complex128) in 1–2 GP/XMM registers (RDI…R9 + XMM0–7, separate counters,
  all-or-nothing), MEMORY class (>16B) as by-value stack copies at `[RSP+0]`,
  returns ≤16B in RAX:RDX / XMM0:XMM1 pairs and >16B via sret, no shadow
  space (register params spill to callee-allocated homes in
  `p->abi_slot_home`), `AL` = #XMM regs for C varargs, plain `SUB RSP`.
  Known deviations: `f16` travels as a GP scalar, raw unions classify
  INTEGER. darwin/linux targets are gated to `-build-mode:obj` in main.cpp
  (still COFF objects; no unix linking yet).

How the harness works:
1. Cross-generate an object: windows target for Win64 ABI, darwin for SysV.
2. `extract_text.py obj text.bin [text_syms.h]` pulls `.text` out of the COFF
   object, applies intra-section REL32 relocations (position-independent blob),
   prints exported symbol offsets, and optionally writes them as a C header.
3. `runner.c` (compiled `clang -arch x86_64` → runs under Rosetta) mmaps the
   blob RWX and calls it: plain C calls for SysV blobs, or `-DWIN64_ABI` for
   `__attribute__((ms_abi))` calls into Win64 blobs.

Usage (from repo root):

```sh
# SysV (native C calls):
mkdir -p x64_rosetta/out
./odin build x64_rosetta/rosetta_test.odin -file -x64-backend \
    -target:darwin_amd64 -build-mode:obj -no-entry-point -no-bounds-check \
    -out:x64_rosetta/out/rosetta_test.obj
cd x64_rosetta
python3 extract_text.py out/rosetta_test_x64.obj text.bin text_syms.h
clang -arch x86_64 -O1 -o runner runner.c && ./runner text.bin

# Win64 regression (same tests through ms_abi):
# ... -target:windows_amd64 -out:x64_rosetta/out_win/... then
# clang -arch x86_64 -O1 -DWIN64_ABI -o runner_win runner.c && ./runner_win text_win.bin
```

Verified 2026-07-06 (M4, Rosetta 2), both ABIs, all 22 tests pass: scalars,
recursive fib (REL32), mixed f64/i64 args, 8-arg calls (stack args both
sides), and aggregates against clang-compiled C callers: INT×2 / SSE×2 /
mixed register pairs (arg + return), 8-byte SSE structs, 24-byte MEMORY
args, sret returns, Odin `string` passed from C, and an Odin→Odin
roundtrip of all of the above. Full `examples/demo` codegen (46 objects)
also completes assert-free for both targets.

Test coverage limits: only code whose relocations stay inside `.text` (no
`.rdata`/`.data`, no external runtime calls, no TLS — the Win64 `gs:[0x58]`
TLS sequence would fault under macOS). Next steps for real unix support:
SysV eightbyte classification for aggregates, Mach-O/ELF writer, `.eh_frame`
unwind, darwin TLS.
